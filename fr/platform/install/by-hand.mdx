Ce que [`fireflo-install`](/platform/install/one-command) automatise. Lisez ceci si vous packagez FireFlo vous-même, ou si une étape d'installation a échoué et que vous devez savoir ce qu'elle faisait.

## Prérequis

- **Java 25.** La build cible la release 25 et **ne tournera pas sur 21**.
- **PostgreSQL 14 ou plus récent.** Optionnel pour le gateway seul en mode fichier ; requis pour le control panel, le crédit prépayé, le whitelisting et les enregistrements d'appels en table.
- **RabbitMQ**, seulement si les messages soumis doivent survivre à un redémarrage du gateway. Sans lui la file est en mémoire et un redémarrage supprime tout ce qui n'a pas atteint un vendeur.
- Un utilisateur de service sans shell de connexion.

## La partie inconfortable de cette plateforme

Deux des trois runtimes ne sont **pas** ce qu'Ubuntu fournit :

| Besoin | Ubuntu 24.04 fournit | Faire |
| :--- | :--- | :--- |
| Java 25 | `openjdk-21` | Ajouter Adoptium |
| Node 22 | `nodejs` 18 | Ajouter NodeSource |
| PostgreSQL 14+ | PostgreSQL 16 | `apt install postgresql` |

<Steps>
  <Step title="Paquets de base">
```bash
sudo apt update
sudo apt install -y wget curl gpg apt-transport-https ca-certificates ufw nginx postgresql
```
  </Step>
  <Step title="Java 25 depuis Adoptium">
```bash
sudo mkdir -p /etc/apt/keyrings
wget -qO- https://packages.adoptium.net/artifactory/api/gpg/key/public \
  | sudo tee /etc/apt/keyrings/adoptium.asc > /dev/null
echo "deb [signed-by=/etc/apt/keyrings/adoptium.asc] \
https://packages.adoptium.net/artifactory/deb $(lsb_release -cs) main" \
  | sudo tee /etc/apt/sources.list.d/adoptium.list
sudo apt update && sudo apt install -y temurin-25-jdk
java -version        # doit afficher 25
```
  </Step>
  <Step title="Node 22 depuis NodeSource">
Next.js 16 ne tourne pas sur le Node 18 d'Ubuntu. C'est pour le control panel.
```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node --version       # doit afficher v22 ou plus récent
```
  </Step>
  <Step title="Utilisateur de service et répertoires">
```bash
sudo useradd --system --home-dir /opt/fireflo --shell /usr/sbin/nologin fireflo
sudo install -d -o fireflo -g fireflo /opt/fireflo /etc/fireflo /var/lib/fireflo /var/log/fireflo
sudo chmod 750 /etc/fireflo
```
  </Step>
  <Step title="Base de données">
```bash
sudo -u postgres createuser fireflo --pwprompt
sudo -u postgres createdb fireflo --owner fireflo
```
Gardez le mot de passe hors de l'historique du shell. Écrivez-le directement dans le fichier d'environnement.
  </Step>
</Steps>

## Disposition

La configuration est gardée **hors** du répertoire des artefacts, pour qu'une mise à niveau puisse remplacer l'artefact en gros sans toucher à ce que vous avez édité.

```text
/opt/fireflo/            possédé par fireflo, REMPLACÉ à la mise à niveau
  quarkus-run.jar
  lib/  app/  quarkus/
  bin/fireflo            la CLI opérateur, gardée hors de ce qu'une mise à niveau remplace

/etc/fireflo/            possédé par fireflo, JAMAIS remplacé à la mise à niveau
  fireflo.env            environnement, y compris le mot de passe de la base. chmod 600
  smsg.properties        workers et paramètres      \
  credentials.yml        logins                     |  mode fichier uniquement
  routingTable.conf      routage                    |
  rates.conf             tarifs                    /

/var/lib/fireflo/        le stockage des accusés, et les CDR quand il n'y a pas de base
/var/log/fireflo/        logs
```

<Warning>
**L'artefact est un répertoire, pas un fichier.** `quarkus-run.jar` ne tournera pas sans les répertoires `lib/`, `app/` et `quarkus/` à côté. Copier le jar seul produit un processus qui démarre puis échoue à trouver ses classes.
</Warning>

## Le fichier d'environnement

`chmod 600`. Il contient le mot de passe de la base et les deux tokens opérationnels.

```bash
export FIREFLO_CONF_DIR=/etc/fireflo
export FIREFLO_DB_URL=jdbc:postgresql://localhost:5432/fireflo
export FIREFLO_DB_USER=fireflo
export FIREFLO_DB_PASSWORD=...
export FIREFLO_CONFIG_SOURCE=file
export QUARKUS_HTTP_PORT=8080
export FIREFLO_OPS_PORT=9000
```

<Warning>
Définissez `FIREFLO_CONF_DIR` sur un **chemin absolu**. Une valeur relative, y compris le défaut `conf`, se résout par rapport au répertoire de travail du processus. Donc une unit avec `WorkingDirectory=/opt/fireflo` lit `/opt/fireflo/conf/`, qui n'est pas où vous avez édité quoi que ce soit.
</Warning>

## Ports

| Port | Porte | Exposer à |
| :--- | :--- | :--- |
| 8080 | L'API REST | Clients |
| 27777 | Binds SMPP | Clients |
| 9000 | `/ops/*` et `/q/metrics` | **Loopback, ou votre propre réseau uniquement** |
| 3000 | Le control panel | Derrière TLS |

## systemd

Deux paramètres comptent plus que le reste :

```ini
# une session SMPP bindée est la connexion d'un client, donc arrêter délibérément plutôt qu'abruptement
KillSignal=SIGTERM
TimeoutStopSec=30

# un descripteur de fichier par session client bindée, plus les connexions vendeurs
LimitNOFILE=65535
```

<Warning>
`SIGTERM` plutôt que `SIGKILL` n'est pas une politesse. Un arrêt propre restitue le **crédit prépayé réservé** non dépensé ; un `kill -9` le bloque jusqu'à ce que [`fireflo credit release`](/reference/cli/fireflo) tourne.
</Warning>

## Rétention des logs, que vous possédez maintenant

Rien dans le gateway ne supprime `httpapi.log`. Quarkus le tourne quotidiennement et garde chaque fichier pour toujours. `fireflo-install` écrit une règle `tmpfiles.d` exactement pour cela ; **installer à la main signifie en écrire une vous-même, ou accepter une croissance non bornée.** Voir [Logging](/reference/config/logging).

## Vérifier

```bash
scripts/fireflo verify
```

Et vérifiez que les deux tokens sont vraiment séparés. Lire avec le token admin doit renvoyer **404** :

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  -H "Authorization: Bearer $FIREFLO_OPS_ADMIN_TOKEN" \
  http://localhost:9000/ops/health      # attendu 404
```
