---
title: "Plusieurs instances sur un hôte"
description: "Un mot nomme l'instance d'un client aux deux installateurs, et l'isolation qu'un virtualhost apporte."
---

Des déploiements séparés sur un hôte. Un par client, ou un par environnement. **Pas un cluster** : ce sont des gateways indépendants avec leurs propres bases et leur propre trafic. Pour la raison pour laquelle plusieurs instances contre *une seule* base ne fonctionnent pas, voir [Cluster](/platform/install/clustering).

## Un nom, deux produits

```bash
sudo ./scripts/fireflo-install       install --tenant websmsc
sudo ./scripts/fireflo-panel-install install --tenant websmsc
```

`--tenant` est toute l'idée : **le même mot nomme la même instance aux deux installateurs**. Un nom par client, deux produits.

| | Chemin | Unit |
| :--- | :--- | :--- |
| Gateway | `/srv/fireflo/websmsc/gateway` | `fireflo-websmsc` |
| Panel | `/srv/fireflo/websmsc/panel` | `fireflo-websmsc-panel` |

## À la mise à jour c'est une recherche, pas une disposition

C'est la partie qui empêche l'erreur coûteuse.

```bash
sudo ./scripts/fireflo-install update --tenant websmsc
```

Sur `update`, `service` et `rollback`, `--tenant` **trouve** l'installation avec ce nom et utilise ses propres chemins, unit, compte et ports.

<Warning>
Sans cela, une mise à niveau visée en oubliant un drapeau arrêterait une unit qui pourrait ne pas exister, remplacerait un répertoire appartenant à une autre instance, et activerait un second service contre la même base.

Une unit dont `WorkingDirectory=` nomme une installation différente est **refusée, avant que quoi que ce soit ne soit arrêté**.
</Warning>

## Ports

```bash
--smpp-port-range 27777-27800
```

Donnez une plage et l'installateur prend le prochain port listener libre, pour que l'instance deux n'entre pas en collision avec l'instance un. `--http-port` et `--ops-port` sont aussi définis par instance.

Les deux installateurs relisent les ports depuis le fichier d'environnement à `update`, donc une instance sur des ports non par défaut cesse d'échouer son propre verify à la fin de chaque mise à niveau.

## Un virtualhost

```bash
sudo ./scripts/fireflo-install install --tenant websmsc --vhost /home/websmsc
```

Place l'instance sous une home par client : `/home/websmsc/gateway`, avec le panel à `/home/websmsc/panel`.

**Ce que cela apporte :** les deux units générées montent un **tmpfs sur `/home`** et n'y re-lient que ce virtualhost, donc un gateway ne peut pas voir le répertoire home d'un autre client.

<Warning>
Sous `--vhost`, le `CDR_EXPORT_DIR` du panel doit aussi se trouver dans une racine `BindPaths=`. **Cet échec est silencieux.** Les exports sont préparés puis ne peuvent pas être lus.
</Warning>

<Note>
`--vhost` **seul**, sans `--tenant`, garde son ancienne signification plate, donc les panels déjà installés sous `/home/<nom>` sont atteints exactement comme avant. Cette compatibilité est délibérée : une mise à niveau ne doit pas relocaliser une installation en cours.
</Note>

Les trois drapeaux de répertoire (`--app-dir`, `--conf-dir`, `--data-dir`) l'emportent toujours sur l'un ou l'autre schéma là où ils sont donnés.

## Ce dont chaque instance a besoin en propre

| | Partagé ? |
| :--- | :--- |
| Base de données | **Non**, une par instance |
| Listener, ports HTTP et ops | **Non** |
| Tokens opérationnels | **Non**, générés par installation |
| Compte de service | Optionnel, `--user` |
| Hôte, paquets, Java, Node | Oui |
