title: "rates.conf"
description: "The rate grammar, what a scope means on each side of the trade, and the reserved scope that prices accounts you have not created yet."
---

The same grammar as [`routingTable.conf`](/reference/files/routing-table), with the per-unit amount
where routing puts the target.

```
Amount:Attribute:Operator:Value
```

Rules are grouped under a `[scope]` header and evaluated top to bottom **within it**. The first match
wins, so specific rules go above the catch-all.

## A scope is one side of the trade

| Scope | Means |
| :--- | :--- |
| A **vendor** instance name | What that vendor charges you — **cost** |
| An **account** id | What you charge that customer — **price** |
| `[*]` | Prices **any account with no rules of its own**, including accounts created later |

<Warning>
`[*]` is **sell side only**. A vendor never inherits it, so a cost with no rule stays unknown rather
than quietly becoming the sale price — which would report a margin of zero on traffic you are in fact
paying for.
</Warning>

Nothing in the schema distinguishes a vendor scope from an account scope; the gateway tells them apart
by which lookup asks. `fireflo import --dry-run` classifies every scope and **names the ones it can
classify as neither** — which is how a scope that will load and silently match nothing gets caught.

## Amounts

Decimal, at most **4** decimal places. Parsed exactly, never through floating point, so `0.0450` means
`0.0450`.

<Note>
`smsg.money.scale` controls how many places a **total** is published with. Per-message rates always
keep four, because `0.0450` shown as `0.05` is 11% out on every message. See
[Rating](/reference/config/rating).
</Note>

## Conditions

Attributes are the routing engine's: `to`, `from`, `body`, `product`, `systemId`, `owner_id`, `type`
and the rest. `matches` is a regular expression and is **anchored** — `^61.*` matches a full number,
a bare `61` does not.

Combine conditions with `~~`, which must appear in **all three** positions:

```
0.0800:product~~to:equals~~matches:premium~~^61[0-9]{9}$
```

## The catch-all

```ini
[acct-1001]
0.0800:product:equals:premium
0.0450::default:
```

<Warning>
**Without a `default`, a message that matches nothing is recorded as an UNKNOWN rate, not as free.**
That is the honest outcome, and it means the message is delivered and billed to nobody until you
notice. `smsg.rating.unrated.refuse` turns it into a refusal instead.
</Warning>

## Worked shape

```ini
# What vendor1 charges us
[vendor1]
0.0310:to:matches:^61[0-9]{9}$
0.0400::default:

# What acct-1001 pays us
[acct-1001]
0.0800:product:equals:premium
0.0450::default:

# Every account with no rules of its own
[*]
0.0500::default:
```

Cost and price live in the same file and are the same grammar, which is why the control panel groups
them as **What we pay** and **What we charge** rather than mixing them in one list.

In database mode this file is not read after startup; the same data lives in `app_rate_rule` and its
condition tables. See [Database](/reference/config/database) and
[How pricing works](/platform/billing/how-pricing-works).
