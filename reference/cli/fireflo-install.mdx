Installs and upgrades the **gateway**. The control panel has its own installer —
[`fireflo-panel-install`](/reference/cli/fireflo-panel-install).

## The five verbs

| Verb | Does | Never touches |
| :--- | :--- | :--- |
| `check` | Is this host ready. Changes nothing. | Everything |
| `install` | First install: packages, service user, directories, artefact, configuration, database, systemd unit, firewall, smoke test | An existing conf directory — it refuses instead |
| `update` | Replaces **the artefact only** | The conf directory |
| `service` | Generates the startup script and unit on an existing install, and starts it | The conf directory |
| `rollback` | Restores the previous artefact | The conf directory |

<Note>
**"Packages" means the installer's own dependencies, not the services FireFlo talks to.** It installs
`curl`, `openssl`, `rsync`, `python3` and the PostgreSQL **client** — never a PostgreSQL server,
never a broker, and never Node. On a bare host, run
[`setup.sh`](/platform/install/prepare-a-host) first.
</Note>

<Warning>
**`install` refuses when a configuration directory already exists**, rather than minting a second pair
of operational tokens over the top of the first. If you have configuration but no service, the verb
you want is `service`, not `install`.

That refusal keys on `$CONF_DIR/fireflo.env`, so it does **not** fire when you install the same tenant
at a *different* path. Such a run gets as far as generating a second pair of tokens before the unit
step refuses on the name collision. Remove the old install first — see [Removing a
tenant](/platform/install/multiple-instances#removing-a-tenant).
</Warning>

<Note>
**There is no `uninstall` verb.** Removal is manual, and a tenant is more units than it looks:
the gateway writes `fireflo-<name>.service` plus a `-logclean.timer` and `-logclean.service` pair.
</Note>

## Options worth knowing

### Layout and identity

| Option | Purpose |
| :--- | :--- |
| `--tenant NAME` | Names this instance. On `update`, `service` and `rollback` it is a **lookup** — the install with that name is found and its own paths, unit, account and ports are used, so an upgrade cannot be aimed at the wrong instance by forgetting a flag. |
| `--vhost PATH` | Puts the instance in a per-customer virtualhost — `--tenant websmsc --vhost /home/websmsc` gives `/home/websmsc/gateway`, with the panel alongside at `/home/websmsc/panel`. |
| `--conf-dir` / `--app-dir` / `--data-dir` / `--log-dir` | Individual paths. |
| `--user` / `--group` / `--service-name` | The service account and unit name. **Under `--vhost`, `--user` must be the account that owns the virtualhost** — the installer never chowns a directory that already exists, so any other account cannot traverse it. |

Both generated units mount a **tmpfs over `/home`** and bind only the one virtualhost back in, so a
gateway cannot see any other customer's home directory. That is a namespace, not a permission: the
directory's own mode still decides who may enter it, which is why `--user` matters above.

<Note>
**Refused because the application directory is an account's home.** An update replaces the
application directory wholesale, so the installer refuses any layout where that is a real home under
`/home` or `/root`. Under `--vhost` the fix is the account, not the path: pass `--user` with the
account that owns the virtualhost, or give the service account the virtualhost as its home
(`usermod -d /home/<name> <account>`).

The 0.11.3 tarball as first published refused **every** first `--vhost` install for a service
account that did not exist yet, and suggested a second `--vhost` that would have nested the install
inside itself. On a host with that installer, pass `--user` with an existing account.
</Note>

<Note>
Every flag takes a **space-separated** value. `--vhost=/home/acme` is rejected as an unknown option
rather than parsed.
</Note>

### Configuration and database

| Option | Purpose |
| :--- | :--- |
| `--config-source file\|db` | Which source the instance starts in. |
| `--db-*` | Database connection details. |
| `--bootstrap` / `--import` | Populate a fresh database, or bring an existing file configuration in. |
| `--country` / `--country-code` / `--product` / `--rate` / `--decimals` / `--currency` | The first tariff. |

### Behaviour

| Option | Purpose |
| :--- | :--- |
| `--whitelist` / `--no-whitelist` | Whether sender-ID and content checking starts on. |
| `--balance` / `--no-balance` | Whether prepaid credit is enforced. |
| `--smpp-port` / `--smpp-port-range` / `--http-port` / `--ops-port` | Ports. A range lets the installer pick the next free listener port. |
| `--broker-uri` / `--broker-queue` / `--no-broker` | RabbitMQ for the REST path. |
| `--log-backups` / `--log-retain-days` | Log retention, including the daily timer that reaps `httpapi.log`. |
| `--with-fail2ban` / `--no-fail2ban` | Whether fail2ban watches this install's refused logins and blocks the addresses behind them. **Off by default.** |
| `--fail2ban-ignore A,B` | Addresses or CIDRs that must never be banned. |
| `--with-smppsim` / `--no-smppsim` | Also install SMPPSim, a test SMSC, as its own service, and route `MESSAGE` to it. `--bootstrap` installs only. **Off by default.** |
| `--smppsim-port` / `--smppsim-console-port` | SMPPSim's ports, default 7775 and 7788. Never opened in the firewall. |
| `--vendor-cost RATE` / `--opening-balance AMOUNT` | A cost on SMPPSim, and prepaid credit on the first account. |

<Warning>
Also `fireflo-install fail2ban`, which turns blocking on for an install that already exists — the
same step, reachable without reinstalling.

**`--with-fail2ban` edits host security configuration**, and grants the control panel one narrow
`sudo` rule. That is why it is opt-in rather than something an upgrade turns on: a jail that arrives
by surprise is how an install starts refusing its own customers.

Fill in the never-ban list before you rely on any of it. A ban is on an address, and an address
usually carries a whole customer — see
[Blocking abusive clients](/platform/operations/blocking-abusive-clients).
</Warning>

### Running it

| Option | Purpose |
| :--- | :--- |
| `--yes` | Do not prompt. |
| `--dry-run` | Show what would happen. |
| `--no-packages` / `--no-systemd` / `--firewall` / `--no-firewall` | Skip a stage. |
| `--sudo` / `--no-sudo` | Privilege escalation. |

<Note>
**`--dry-run` shows less than you might expect.** It cannot report what a package manager would pull
in, or what a migration would find in a database it has not connected to. Read it as "the decisions
this script would make", not "everything that would change on this host".
</Note>

## Trying it with SMPPSim

The release includes **SMPPSim**, a third-party test SMSC (GPL-2; its licence and source are in
`smppsim/`). `--with-smppsim` installs it beside the gateway, as its own systemd unit, and has
bootstrap add it as the vendor `smppsim` with a catch-all in `MESSAGE` — so a message can be sent,
priced, delivered and debited the moment the install finishes. The install then runs
[`fireflo selftest`](/reference/cli/fireflo#selftest) and prints its result.

<Warning>
**SMPPSim accepts everything and invents delivery receipts.** It is for trying FireFlo out, never for
customer traffic — replace it with a real vendor first. It needs a Java runtime, which the installer
adds from your distribution for SMPPSim alone. It listens on every interface and its console can
inject messages, so keep a firewall in front of ports 7775 and 7788; the installer never opens them.
</Warning>

## What it does not install

The **control panel**. That is `fireflo-panel-install`, and on a fresh host you run both.

`--log-retain-days` installs a daily systemd timer that deletes rotated logs, never touching the five
live ones. **Installing by hand means arranging that yourself** — see [Logging](/reference/config/logging).

See [Install in one command](/platform/install/one-command) for the walkthrough.
