Installs and upgrades the **control panel**, which serves both the operator screens and the customer
portal.

<Note>
The panel edits configuration and reads call records. It is **not on the message path**: a panel that
is down costs you the ability to make changes, not the ability to send.

**Install it after the gateway.** The gateway owns the database schema; the panel only reads and
writes rows in it.
</Note>

## The five verbs

| Verb | Does | Never touches |
| :--- | :--- | :--- |
| `check` | Is this host ready. Changes nothing. | Everything |
| `install` | Node, service user, directories, source, `npm ci`, build, environment, systemd unit, then a check that it answers | — |
| `update` | Pulls a new build over an existing install | **The environment file** |
| `service` | Generates the unit on an existing install, and starts it | The environment file |
| `passwd` | Rolls the operator password and restarts | Everything else |

`install` asks for what it needs first and changes nothing until you agree.

## Why `passwd` exists as a verb

**There is no user table.** `OPERATOR_USERNAME` and `OPERATOR_PASSWORD` in `panel.env` are the whole
operator account. `passwd` is therefore the supported way to change it — it rewrites the environment
file and restarts the unit in one step, rather than leaving you to edit a file the installer otherwise
promises never to replace.

## Layout

| Option | Default | Notes |
| :--- | :--- | :--- |
| `--app-dir PATH` | `/opt/fireflo-panel` | Replaced by an update |
| `--conf-dir PATH` | `/etc/fireflo-panel` | **Never replaced** |
| `--data-dir PATH` | `<app-dir>/tmp` | Prepared CSV exports and anything else the panel writes. Preserved by an update; never replaced |
| `--tenant NAME` | — | Installs into `/srv/fireflo/NAME/panel` as unit `fireflo-NAME-panel` |
| `--vhost PATH` **with** `--tenant` | — | `PATH/panel`, with the gateway at `PATH/gateway` |
| `--vhost PATH` **alone** | — | Legacy flat layout: `PATH/app`, `PATH/conf`, `PATH/data` |
| `--port N` | `3000` | **Never derived from `--tenant`** — a second panel on one host needs its own |
| `--user NAME` | `fireflo` | **Required under `--vhost`**: it must be the account that owns the virtualhost, or nothing running as the service can traverse it |

**`--tenant` is the point of the shared vocabulary**: the same word names the same instance to the
gateway installer. One name per customer, two products. The three directory flags still win over
either scheme.

<Warning>
`--vhost` **alone** keeps an older flat meaning, so panels already installed under `/home/<name>` are
reached exactly as before — an upgrade must not relocate a running install. For a **new** tenant that
is almost never what you want: it puts the panel in `PATH/{app,conf,data}` while the gateway sits in
`PATH/gateway`, and `update --tenant NAME` then no longer finds the panel. Give both flags together.
</Warning>

<Note>
Flags take **space-separated** values. `--vhost=/home/acme` is rejected as an unknown option.
</Note>

## What it derives, and the one thing it does not

Given the gateway's conf directory (`--gateway-conf-dir`), the installer derives three things rather
than asking you to copy them: both operational tokens, the read-only database connection, and the ops
URL.

The ops URL is built from that gateway's recorded `FIREFLO_OPS_PORT`, so an instance on a non-default
`--ops-port` needs no second flag here. It was once assumed to be 9000, and the symptom of getting it
wrong is *"Could not reach the gateway: fetch failed"* on every page showing live state — which reads
as the gateway being down rather than as the panel looking at the wrong port.

<Warning>
**`--config-url` is never derived.** The read-write connection to the configuration tables is the one
that can change what customers are charged, so it is always stated rather than inferred. Without it
the panel reports every configuration domain as not editable, rather than failing at the first save.

Passed as a flag it puts the database password in shell history and in `ps` output. Omit it and the
installer prompts instead — and that prompt accepts the literal word **`same`**, meaning "reuse the
connection just derived from the gateway", which is correct whenever one role owns the tenant's
database.
</Warning>
