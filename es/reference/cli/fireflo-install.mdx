Instala y actualiza el **gateway**. El panel de control tiene su propio instalador —
[`fireflo-panel-install`](/reference/cli/fireflo-panel-install).

## Los cinco verbos

| Verbo | Hace | Nunca toca |
| :--- | :--- | :--- |
| `check` | Comprueba si el host está listo. No cambia nada. | Todo |
| `install` | Primera instalación: paquetes, usuario de servicio, directorios, artefacto, configuración, base de datos, unidad systemd, firewall, prueba de humo | Un directorio de configuración existente — se niega en su lugar |
| `update` | Reemplaza **solo el artefacto** | El directorio de configuración |
| `service` | Genera el script de arranque y la unidad sobre una instalación existente, y la inicia | El directorio de configuración |
| `rollback` | Restaura el artefacto anterior | El directorio de configuración |

<Warning>
**`install` se niega cuando ya existe un directorio de configuración**, en lugar de crear un segundo
par de tokens operacionales sobre el primero. Si tienes configuración pero no servicio, el verbo que
quieres es `service`, no `install`.
</Warning>

## Opciones que vale la pena conocer

### Diseño e identidad

| Opción | Propósito |
| :--- | :--- |
| `--tenant NAME` | Nombra esta instancia. En `update`, `service` y `rollback` es una **búsqueda** — se encuentra la instalación con ese nombre y se usan sus propias rutas, unidad, cuenta y puertos, de modo que una actualización no pueda apuntar a la instancia equivocada por olvidar un flag. |
| `--vhost PATH` | Coloca la instancia en un virtualhost por cliente — `--tenant websmsc --vhost /home/websmsc` da `/home/websmsc/gateway`, con el panel al lado en `/home/websmsc/panel`. |
| `--conf-dir` / `--app-dir` / `--data-dir` / `--log-dir` | Rutas individuales. |
| `--user` / `--group` / `--service-name` | La cuenta de servicio y el nombre de la unidad. **Bajo `--vhost`, `--user` debe ser la cuenta propietaria del virtualhost** — el instalador nunca cambia el propietario de un directorio que ya existe, así que ninguna otra cuenta puede recorrerlo. |

Ambas unidades generadas montan un **tmpfs sobre `/home`** y reintroducen únicamente el virtualhost,
de modo que un gateway no puede ver el directorio personal de ningún otro cliente. Eso es un
namespace, no un permiso: el modo del propio directorio sigue decidiendo quién puede entrar, y por
eso `--user` importa arriba.

<Note>
Cada flag toma un valor **separado por espacio**. `--vhost=/home/acme` es rechazado como opción
desconocida en lugar de ser parseado.
</Note>

### Configuración y base de datos

| Opción | Propósito |
| :--- | :--- |
| `--config-source file\|db` | Con qué fuente arranca la instancia. |
| `--db-*` | Detalles de conexión a la base de datos. |
| `--bootstrap` / `--import` | Poblar una base de datos nueva, o traer una configuración de archivo existente. |
| `--country` / `--country-code` / `--product` / `--rate` / `--decimals` / `--currency` | La primera tarifa. |

### Comportamiento

| Opción | Propósito |
| :--- | :--- |
| `--whitelist` / `--no-whitelist` | Si arranca activa la comprobación de sender-ID y contenido. |
| `--balance` / `--no-balance` | Si se aplica el crédito prepago. |
| `--smpp-port` / `--smpp-port-range` / `--http-port` / `--ops-port` | Puertos. Un rango permite al instalador elegir el siguiente puerto de listener libre. |
| `--broker-uri` / `--broker-queue` / `--no-broker` | RabbitMQ para la ruta REST. |
| `--log-backups` / `--log-retain-days` | Retención de logs, incluida la regla de `tmpfiles.d` que limpia `httpapi.log`. |

### Ejecución

| Opción | Propósito |
| :--- | :--- |
| `--yes` | No preguntar. |
| `--dry-run` | Muestra lo que ocurriría. |
| `--no-packages` / `--no-systemd` / `--firewall` / `--no-firewall` | Omitir una etapa. |
| `--sudo` / `--no-sudo` | Escalada de privilegios. |

<Note>
**`--dry-run` muestra menos de lo que podrías esperar.** No puede reportar qué instalaría un gestor
de paquetes, ni qué encontraría una migración en una base de datos a la que no se ha conectado.
Léelo como "las decisiones que este script tomaría", no como "todo lo que cambiaría en este host".
</Note>

## Qué no instala

El **panel de control**. Eso es `fireflo-panel-install`, y en un host nuevo ejecutas ambos.

`--log-retain-days` escribe una regla de `tmpfiles.d` que borra logs rotados, sin tocar nunca los
cuatro logs activos. **Instalar a mano implica encargarte tú de eso** — consulta
[Logging](/reference/config/logging).

Consulta [Instalar en un solo comando](/platform/install/one-command) para el recorrido guiado.
