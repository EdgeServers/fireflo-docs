## Conectarse

| Variable | Usada por | Notas |
| :--- | :--- | :--- |
| `FIREFLO_DB_URL` / `FIREFLO_DB_USER` / `FIREFLO_DB_PASSWORD` | `db`, `bootstrap`, `import`, `show`, `usage`, `purge` | Las mismas variables que lee la pasarela, así que sourcear su fichero de entorno es toda la configuración. |
| `FIREFLO_OPS_URL` | todo en el puerto operacional | La interfaz **de gestión**, 9000 por defecto. |
| `FIREFLO_OPS_TOKEN` | `health`, `version`, `verify` | Debe coincidir con `smsg.ops.token`. |
| `FIREFLO_OPS_ADMIN_TOKEN` | `reload`, `test-bind`, `disconnect`, `capture`, `credit release`, los seis verbos de control | Debe coincidir con `smsg.ops.admin.token`. |
| `FIREFLO_SEND_LOGIN` / `FIREFLO_SEND_PASSWORD` | `send` | Una credencial de cliente: este verbo pasa por el puerto de **mensajes**. |
| `FIREFLO_CONF_DIR` | `verify` | Dónde buscar la configuración que comprueba. |

## Las cuatro banderas de permiso

Cada una existe porque el comando que protege es destructivo de una forma que no es obvia por su
nombre. Ninguna tiene equivalente en línea de comandos, a propósito: una bandera que hay que
exportar es una que no se puede pasar por accidente desde el historial del shell.

| Variable | Requerida por | Protege contra |
| :--- | :--- | :--- |
| `FIREFLO_DB_MIGRATE=true` | `db migrate`, `db repair` | Aplicar DDL forward-only a la base de datos equivocada. |
| `FIREFLO_CONFIG_IMPORT=true` | `import` (no `--dry-run`) | Reemplazar las reglas que deciden qué se cobra a los clientes. |
| `FIREFLO_CDR_PURGE=true` | `usage purge` | Borrar call records: el único registro por mensaje de lo que se cobró. |
| `FIREFLO_DB_RESET=true` | `purge --reset-database` | Vaciar todas las tablas. También rechaza mientras la pasarela sea alcanzable, y le pide teclear el nombre de la base de datos. |

<Note>
`FIREFLO_DB_MIGRATE` y `FIREFLO_CONFIG_IMPORT` son deliberadamente independientes. Una aplica
cambios de esquema; la otra reemplaza precios y credenciales. Un despliegue contento con
automigrar no está necesariamente contento con que le sobrescriban sus tarifas.
</Note>

## Códigos de salida

| Código | Significado |
| :--- | :--- |
| `0` | Bien |
| `1` | Falló |
| `2` | Rechazado, o mal usado: nada se ha tocado |
| `4` | Solo `verify`: el despliegue es correcto, los datos propios de esta instalación no lo son |

La separación `1` / `2` es lo que permite a un pipeline de despliegue distinguir una bandera
ausente de una migración rota.
