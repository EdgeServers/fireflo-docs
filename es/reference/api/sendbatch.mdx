---

Encola muchos mensajes en una llamada. **La respuesta confirma solo la aceptación:** los
resultados por mensaje llegan a su URL de errback.

```json
{
  "messages": [
    { "to": "61491570006", "content": "Your OTP is 4417." },
    { "to": "61491570007", "content": "Your OTP is 9921." }
  ]
}
```

```json
{
  "data": {
    "batchId": "c0ffee12-9f3a-4a1e-8d55-1b2c3d4e5f60",
    "messageCount": 3,
    "scheduled": "3600s"
  }
}
```

<Warning>
**`messageCount` es a cuántos se expandió el lote, no cuántos tuvieron éxito.** No hay ids por
mensaje en esta respuesta ni resultados por mensaje. Véase
[Callbacks de lote](/developers/receive/batch-callbacks).
</Warning>

## Campos

| Campo | Tipo | Obligatorio | Notas |
| :--- | :--- | :--- | :--- |
| `messages` | array | **sí** | Un objeto por mensaje, cada uno tomando los campos de un envío único. Su `to` puede también ser un array. |
| `globals` | object | no | Valores por defecto **fusionados bajo** cada mensaje, así que un campo fijado en un mensaje gana. |
| `batch_config` | object | no | `schedule_at`, `callback_url`, `errback_url`. |

<Warning>
**Otras claves en `batch_config` se ignoran, no se rechazan.** Un `errback_url` mal escrito le
cuesta cada resultado por mensaje mientras el lote sigue devolviendo `200`.

Este es el único lugar de la API donde un tecleo erróneo no produce un `400`. Verifíquelo
enviando un lote con un mensaje que sepa que será rechazado.
</Warning>

## `schedule_at`

Exactamente dos formas:

| Forma | Significado |
| :--- | :--- |
| `3600s` | Relativa: dentro de una hora |
| `2026-08-20 09:30:00` | Absoluta, `YYYY-MM-DD HH:MM:SS` |

Cualquier otra cosa es `412 Got unknown format`. **Una fecha en el pasado se rechaza**, no se
envía inmediatamente.

## Errores particulares de este endpoint

| Estado | `message` | Cuándo |
| :--- | :--- | :--- |
| 400 | `Mandatory argument messages is not found.` | Ausente, no es un array o está vacío. |
| 400 | `Argument messages has an invalid value: a batch may expand to at most 10000 messages.` | Los destinos con valor de array multiplicaron por encima del tope. |
| 412 | `Got unknown format: <value>, correct formats are …` | `schedule_at` en ninguna de las formas aceptadas, o en el pasado. |

**El tope es 10 000 tras expansión.** 100 mensajes con 200 destinatarios cada uno son 20 000, y
se rechazan.

## Ritmo y durabilidad

Los lotes **se ritman** contra la profundidad de la cola del router, pausándose por encima de una
marca alta. No necesita ritmar usted mismo el envío de un lote.

<Warning>
**Los lotes programados sobreviven a un reinicio solo con un broker RabbitMQ configurado**, y ni
siquiera entonces cuando la conexión con el broker está degradada. Si la programación durable
importa, confirme con su proveedor qué proveedor de colas ejecuta.
</Warning>

## No hay endpoint de estado de lote

Ni en FireFlo ni en Jasmin. El `batchId` correlaciona los callbacks que recibe; no hay nada que
consultar.
