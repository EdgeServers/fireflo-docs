---
title: "Instalar el panel de control"
description: "El instalador del panel, qué deriva de la configuración del gateway y la única conexión que nunca adivina."
---

El panel de control sirve tanto las pantallas del operador como el portal del cliente. Es un proceso
independiente con su propio instalador y su propio archivo de entorno.

<Note>
**Instálalo después del gateway.** El gateway es dueño del esquema de la base de datos; el panel solo
lee y escribe filas en ella.

**No está en la ruta de mensajes** — un panel caído te cuesta la capacidad de hacer cambios, no la de
enviar.
</Note>

## Instalar

```bash
./scripts/fireflo-panel-install check
sudo ./scripts/fireflo-panel-install install
```

`install` se encarga de Node, usuario de servicio, directorios, código fuente, `npm ci`, build,
entorno, unidad systemd, y luego comprueba que responde. Pregunta primero lo que necesita y no cambia
nada hasta que aceptas.

## Qué deriva

Dado el directorio de configuración del gateway, el instalador lee los **tokens operacionales** y la
**conexión de base de datos de solo lectura** en lugar de pedirte que los copies a mano.

<Warning>
**`--config-url` nunca se deriva.** La conexión de lectura-escritura a las tablas de configuración es
la que puede cambiar lo que se cobra a los clientes, así que siempre se indica explícitamente.

Sin ella, el panel reporta cada dominio de configuración como **no editable**, en lugar de fallar en
el primer guardado.
</Warning>

## La cuenta del operador son dos variables de entorno

No hay tabla de usuarios.

```bash
sudo ./scripts/fireflo-panel-install passwd
```

Esa es la forma soportada de cambiarla — reescribe el archivo de entorno y reinicia la unidad en un
solo paso, en lugar de dejarte editar un archivo que el instalador por lo demás promete no reemplazar
nunca.

## Las dos URL que es fácil confundir

| Variable | Apunta a | Si te equivocas |
| :--- | :--- | :--- |
| `GATEWAY_OPS_URL` | El puerto de **gestión**, 9000 | Las lecturas de estado en vivo devuelven 404 en todo |
| `GATEWAY_API_URL` | El puerto de **mensajería**, 8080 | Cada llamada del playground da 404 |

Son puertos distintos que transportan cosas distintas y no comparten rutas. Ambos fallos parecen una
caída del servicio y no lo son.

## TLS por delante

El panel habla HTTP plano en `PORT` (3000 por defecto). Pon nginx o similar por delante, y establece
`AUTH_URL` al origen público — sin definir, un cierre de sesión redirige a localhost.

`NODE_ENV=production` se aplica tanto al **build** como a la ejecución, porque decide si la cookie de
sesión se marca como segura.

## El inicio de sesión de los clientes necesita correo

Un cliente inicia sesión mediante un enlace mágico. Con `FIREFLO_SMTP_HOST` o `FIREFLO_SMTP_FROM` sin
definir, **ningún cliente puede iniciar sesión** — el portal indica que no se puede enviar el enlace
en lugar de fallar en silencio, pero nadie entra.

Consulta [Acceso al portal](/platform/customers/portal-access).

## Actualizar

```bash
sudo ./scripts/fireflo-panel-install update
```

Reemplaza el build. **Nunca toca el archivo de entorno.**

<Warning>
Actualiza el panel y el gateway **juntos**. La versión del panel repite el release del gateway contra
el que se compiló en sus primeros tres números — `0.7.3.1` va con el gateway `0.7.3` — y lo comprueba
en tiempo de ejecución y lo indica cuando no coinciden.
</Warning>

## Bajo un virtualhost

`--tenant NAME` coloca el panel en `/srv/fireflo/NAME/panel` como unidad `fireflo-NAME-panel`, y la
misma palabra nombra la misma instancia para el instalador del gateway. Con `--vhost PATH` la raíz se
mueve a `PATH/panel`, con el gateway en `PATH/gateway`.

<Warning>
Bajo `--vhost`, `CDR_EXPORT_DIR` debe estar dentro de una raíz de `BindPaths=`. **Ese fallo es
silencioso** — las exportaciones se preparan y luego no se pueden leer.
</Warning>

Todas las variables están en [Entorno del panel de control](/reference/config/control-panel).
