Enfileira muitas mensagens em uma chamada. **A resposta confirma apenas aceitação.** Resultados por
mensagem chegam na sua errback URL.

```json
{
  "messages": [
    { "to": "61491570006", "content": "Your OTP is 4417." },
    { "to": "61491570007", "content": "Your OTP is 9921." }
  ]
}
```

```json
{
  "data": {
    "batchId": "c0ffee12-9f3a-4a1e-8d55-1b2c3d4e5f60",
    "messageCount": 3,
    "scheduled": "3600s"
  }
}
```

<Warning>
**`messageCount` é para quantas o batch se expandiu, não quantas tiveram sucesso.** Não há ids por
mensagem nesta resposta, nem resultados por mensagem. Veja
[Callbacks de batch](/developers/receive/batch-callbacks).
</Warning>

## Campos

| Campo | Tipo | Obrigatório | Observações |
| :--- | :--- | :--- | :--- |
| `messages` | array | **sim** | Um objeto por mensagem, cada um aceitando os campos de um envio único. Seu `to` também pode ser um array. |
| `globals` | object | não | Padrões **mesclados por baixo** de cada mensagem, então um campo definido em uma mensagem vence. |
| `batch_config` | object | não | `schedule_at`, `callback_url`, `errback_url`. |

<Warning>
**Outras chaves em `batch_config` são ignoradas, não recusadas.** Um `errback_url` mal escrito
custa a você cada resultado por mensagem, enquanto o batch ainda retorna `200`.

Este é o único lugar da API em que um erro de digitação não produz um `400`. Verifique enviando um
batch contendo uma mensagem que você sabe que vai ser recusada.
</Warning>

## `schedule_at`

Exatamente duas formas:

| Formato | Significado |
| :--- | :--- |
| `3600s` | Relativo. Em uma hora |
| `2026-08-20 09:30:00` | Absoluto, `YYYY-MM-DD HH:MM:SS` |

Qualquer outra coisa é `412 Got unknown format`. **Uma data no passado é recusada**, não enviada
imediatamente.

## Erros específicos deste endpoint

| Status | `message` | Quando |
| :--- | :--- | :--- |
| 400 | `Mandatory argument messages is not found.` | Ausente, não é um array, ou está vazio. |
| 400 | `Argument messages has an invalid value: a batch may expand to at most 10000 messages.` | Destinos em array multiplicaram e passaram do teto. |
| 412 | `Got unknown format: <value>, correct formats are …` | `schedule_at` em nenhum dos formatos aceitos, ou no passado. |

**O teto é 10 000 após a expansão.** 100 mensagens, cada uma com 200 destinatários, dá 20 000, e é
recusado.

## Pacing e durabilidade

Os batches **se ajustam sozinhos** ao tamanho da fila do roteador, pausando acima de uma marca
d'água. Você não precisa limitar sua própria submissão de um batch.

<Warning>
**Batches agendados sobrevivem a um restart apenas com um broker RabbitMQ configurado**, e nem
mesmo aí enquanto a conexão com o broker está degradada. Se agendamento durável importa, confirme
com seu provedor qual provedor de fila ele roda.
</Warning>

## Não há endpoint de status de batch

Nem no FireFlo, nem no Jasmin. O `batchId` correlaciona os callbacks que você recebe; não há nada
para polling.
